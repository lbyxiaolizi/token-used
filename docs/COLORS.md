# 进度条配色与含义

四个插件的进度条**语义不统一**——这是设计决策（每个场景的「百分比」基准不同），不是 bug。

## 1. 今日总览 (`daily-overview-plugin.py`)

进度条 = **该模型占今天总量的份额**。

| 颜色 | 阈值（占今日总量） |
| :---: | --- |
| 🔴 红 | ≥ 50% — 主力模型 |
| 🟠 橙 | ≥ 25% — 次主力 |
| 🔵 蓝 | < 25% — 一般 |

第一条「今日合计」hero 条目固定蓝色，进度条满（`used = limit`）。

## 2. 单 CLI 插件（Claude Code / Gemini / Codex）

进度条 = **今天用量 ÷ 期内峰值日用量**。

| 颜色 | 阈值（今天 / 峰值日） |
| :---: | --- |
| 🔴 红 | ≥ 100% — 今天破峰 |
| 🟠 橙 | ≥ 80% — 接近峰值 |
| 🔵 蓝 | < 80% — 一般日 |

「期内」由 `STAT_PERIOD` 参数决定（7 天或 30 天）。

## 3. 黄色从哪来

代码里**没有**主动设黄色。如果看到黄色，那是 UsageBoard 内置的「警告状态」UI 渲染——`status` 字段为 `warning` 时框架自己加的提示色。

`status` 设值规则：

| 插件 | normal | warning | critical |
| --- | --- | --- | --- |
| 单 CLI | < 80% | 80%-99% | ≥ 100%（破峰） |
| 总览模型条 | 全部 normal | — | — |

所以**只有单 CLI 插件**会触发 warning（黄色）和 critical 状态。

## 想统一规则

如果觉得这套语义乱，最简单的统一方案是**把所有插件都改成「占今日总量份额」**：

```python
# 在每个单 CLI 插件中替换 used/limit 的算法：
used_m  = round(today_total / 1_000_000, 2)
limit_m = max(round(grand_total / 1_000_000, 2), 0.01)  # grand_total = 跨所有源今日合计
displayStyle = "percent"
```

但这要求单 CLI 插件能读到其他源的数据，违反了「单 CLI 只看自己」的设计。可以接受的折中：单 CLI 显示**该 CLI 内**所有模型的份额（已在做，是 hero 条），而不是跨源份额。
